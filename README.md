# 개요

2026년 운영체제 과목 팀 프로젝트를 저장하는 원격 저장소입니다.
이번 팀 프로젝트에서는 CPU 스케쥴러를 제작해볼 예정입니다.

# 작업 순서

**반드시 읽어주셔야 하는 부분입니다**.

1. 개발하기 전 github 이슈 생성
2. `develop` 브랜치에서 작엽 유형에 따라 브랜치를 생성
   - 단, 리팩토링인지, 기능 생성인지에 따라 `refactor/#71`, `feat/#3`처럼 `타입/#이슈번호` 형태로 브랜치를 생성하도록 한다
   - 커밋에 대한 자세한 내용은 [커밋 규칙에 대해 다룬 블로그 글](https://velog.io/@chojs28/Git-커밋-메시지-규칙) 참조
3. 머지는 독단적으로 진행하지 않으며, 반드시 `pull request`를 작성한 뒤 모든 팀원의 확인 및 상의 후에 진행하도록 한다

# 브랜치 관리

작업할 브랜치는 다음과 같이 규정합니다:

- `main`: 작동하는 하나의 완성본을 백업하는 브랜치
- `develop`: 개발 완료된 사항을 바로바로 합쳐보는 브랜치
  - 여기에서 특정 기능이 완성되었다고 판단할 경우, `main` 브랜치로 머지하도록 한다
